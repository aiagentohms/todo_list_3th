02 · this

this: 누가 나를 불렀나

this는 함수를 작성할 때가 아니라 호출하는 순간 정해집니다.

호출 방식 this
obj.method() 점 앞의 객체 obj
fn() window (엄격 모드면 undefined)
new Fn() 새로 만들어진 객체
addEventListener(function) 이벤트가 걸린 요소
() => { } 자기 this 없음 → 바깥 this
스코프는 작성한 위치로, this는 호출한 방식으로 정해진다
02 · this

화살표 함수에는
this가 없다

화살표 함수는 this를 새로 만들지 않고 바깥 스코프의 this를 그대로 씁니다.

  • 일반 함수 핸들러: this = 이벤트가 걸린 요소 (event.currentTarget과 같음)
  • 화살표 함수 핸들러: this = 바깥(전역)의 this → window
  • toss는 event.target으로 “무엇을 눌렀는지”를 직접 찾는다 → this 혼동이 없다
⚠ 객체의 메서드를 화살표 함수로 만들면 this.text가 동작하지 않는다
03 · 실행 컨텍스트

실행 컨텍스트:
함수 실행 준비물 상자

함수가 호출되면 엔진은 필요한 정보를 담은 상자를 먼저 만들고, 그다음 코드를 실행합니다.

실행 컨텍스트 (함수를 호출할 때마다 1개)
변수 환경선언된 변수·함수 목록 → 호이스팅
바깥 환경 참조바깥 스코프와의 연결 → 스코프 체인
this 바인딩호출 방식으로 결정 → this
① 생성 단계 선언부터 등록 › ② 실행 단계 위에서 아래로
스코프와 this는 따로 있는 게 아니라, 모두 이 상자 안에 들어 있다

05 · JSON

JSON에는 데이터만 남는다

JSON으로 바꾸면 값만 남고, 프로토타입 연결(메서드)은 사라집니다.

  • parse 결과는 항상 평범한 객체 → 클래스의 메서드를 쓸 수 없다
  • Date는 문자열이 되고, 함수와 undefined는 아예 빠진다
  • 저장된 값이 없으면 getItem은 null → toss가 || []를 붙인 이유
toss처럼 데이터는 순수 객체로 두고 동작은 함수로 나누면, 저장과 복원이 단순해진다
